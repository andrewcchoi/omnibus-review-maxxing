Overview

Omnibus Review is a sophisticated multi-agent code review system that orchestrates six specialized AI agents to perform deep, comprehensive analysis of codebases. Unlike traditional review tools, it employs parallel specialist agents working independently with advanced reasoning capabilities to catch issues that single-pass reviews miss.

Multi-Agent Architecture

Six specialized agents working in parallel, each focusing on their domain expertise to maximize coverage and depth.

Advanced Reasoning

All agents use Claude Opus 4.5 with ultrathink extended thinking for deeper analysis and fewer false positives.

Automated Fix Cycles

Ralph Loop integration automatically fixes critical and high severity issues with iterative refinement.

Intelligent Aggregation

Deduplicates findings across agents, groups related issues, and produces actionable consolidated reports.

Quick Start

Basic Review

Review all staged changes in the current repository:

/omnibus-review

Review with Auto-Fix

Review and automatically fix critical/high severity issues:

/omnibus-review --fix

Custom Severity Threshold

Only report critical and high severity issues:

/omnibus-review --min-severity high

Specific File Focus

Review only specific files or patterns:

/omnibus-review --files "src/security/*.py"
Tip: Always stage your changes with git add before running omnibus-review. The tool analyzes staged changes to focus on what's actually being committed.

Model Strategy

Why Claude Opus 4.5?

All specialist agents use Claude Opus 4.5 for several critical reasons:

  • Reasoning Depth: Opus excels at complex logical reasoning required for security analysis, architectural assessment, and correctness verification
  • Context Understanding: Superior comprehension of large codebases with interconnected dependencies
  • False Positive Reduction: More nuanced judgment reduces noise from non-issues
  • Pattern Recognition: Better at identifying subtle bugs and anti-patterns across different languages

Extended Thinking (ultrathink)

Each agent is configured with ultrathink extended thinking mode:

  • Deeper Analysis: Agents spend more tokens reasoning about potential issues before reporting
  • Trade-off: Slower reviews (~2-3x time) but significantly higher quality findings
  • Best For: Pre-merge reviews, security audits, production deployments
Cost Consideration: Opus + ultrathink is more expensive than standard models. Use omnibus-review for critical reviews where thoroughness matters more than speed.

Severity Levels

CRITICAL Immediate action required: Security vulnerabilities, data loss risks, production outages
HIGH Fix before merge: Correctness bugs, major performance issues, architectural flaws
MEDIUM Fix soon: Minor bugs, code smells, test gaps, maintainability issues
LOW Consider fixing: Style inconsistencies, minor optimizations, documentation gaps

Ralph Loop Integration

When --fix is enabled or CRITICAL/HIGH issues are detected, omnibus-review automatically initiates a Ralph Loop fix cycle:

  1. Prioritization: Issues sorted by severity (CRITICAL first, then HIGH)
  2. Iterative Fixes: Each issue fixed one at a time with verification
  3. Test Execution: Full test suite runs after each fix to catch regressions
  4. Re-scanning: After fix attempts, re-run review to confirm resolution
  5. Progress Tracking: Live updates showing X/Y issues resolved
  6. Exit Conditions: All issues fixed OR max iterations reached OR tests fail
Ralph Loop is Claude Code's agentic iteration system that can autonomously work on a task list until completion or intervention is needed.

Output Format

Omnibus-review produces a structured report with:

  • Executive Summary: High-level overview of findings by severity
  • Issue Details: Each finding with file, line, description, severity, confidence
  • Agent Attribution: Which specialist(s) identified each issue
  • Related Issues: Grouped findings that share root causes
  • Recommendations: Actionable next steps prioritized by impact
  • Fix Summary: (if --fix used) Resolution status for each issue

See Output Templates for example reports.

Best Practices

When to Use Omnibus Review

  • Pre-merge: Before merging feature branches to main/dev
  • Security audits: Regular security-focused reviews
  • Major refactors: Large architectural changes
  • Production releases: Final check before deployment
  • Onboarding: Review existing code to understand patterns and issues

When NOT to Use

  • WIP commits: Early development with unstaged changes
  • Tiny changes: Single-line typo fixes (use standard /code-review)
  • Urgent hotfixes: When speed matters more than thoroughness
  • Learning exercises: Personal projects where cost matters more than quality

Preparation Checklist

  1. Stage all changes you want reviewed: git add .
  2. Ensure tests are written for new features
  3. Update relevant documentation (README, CLAUDE.md)
  4. Run local linters and formatters first
  5. Consider running with --min-severity high first for faster feedback

See Review Checklist for comprehensive preparation steps.

Troubleshooting

No staged changes found

Solution: Run git add on files you want reviewed, then retry.

Review taking too long

Solutions:

  • Use --files to limit scope to specific areas
  • Use --min-severity high for faster initial pass
  • Consider splitting large changes into smaller reviewable chunks

Too many false positives

Solutions:

  • Increase --confidence threshold (e.g., 0.8 or 0.85)
  • Use --min-severity medium to focus on higher-impact issues
  • Check if project documentation (CLAUDE.md) is up-to-date with patterns

Fix cycle not working

Causes:

  • Tests failing before fixes start (fix test suite first)
  • Issues require manual intervention (human judgment needed)
  • Insufficient context in CLAUDE.md for automated fixes
