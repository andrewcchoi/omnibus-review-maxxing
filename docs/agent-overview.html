The Nine Specialist Agents

Omnibus Review employs nine specialized AI agents. Seven review agents analyze code in parallel, each powered by Claude Opus 4.5 with ultrathink extended thinking. Two fix agents handle the iterative fixing process with context isolation.

Review Agents (7)

🛡️

Security Analyst

Claude Opus 4.5 + ultrathink

Mission: Identify vulnerabilities, attack vectors, and security misconfigurations

Focus Areas:

  • Injection vulnerabilities (SQL, command, LDAP)
  • Authentication and authorization flaws
  • Cryptographic misuse
  • Sensitive data exposure
  • Security misconfiguration
  • Cross-site scripting (XSS)
  • Insecure deserialization
  • Known vulnerable dependencies

Expertise: OWASP Top 10, CWE database, CVE patterns

🏗️

Architecture Reviewer

Claude Opus 4.5 + ultrathink

Mission: Assess design quality, maintainability, and scalability

Focus Areas:

  • Separation of concerns
  • Design pattern adherence
  • Coupling and cohesion
  • Abstraction levels
  • Modularity and reusability
  • Circular dependencies
  • Scalability concerns
  • Technical debt accumulation

Expertise: SOLID principles, design patterns, architectural styles

✓

Correctness Verifier

Claude Opus 4.5 + ultrathink

Mission: Verify logic correctness and identify functional bugs

Focus Areas:

  • Logic errors and edge cases
  • Null/undefined handling
  • Type safety violations
  • Off-by-one errors
  • Race conditions
  • State management issues
  • Error handling completeness
  • Business logic correctness

Expertise: Formal verification techniques, boundary analysis

⚡

Performance Auditor

Claude Opus 4.5 + ultrathink

Mission: Identify performance bottlenecks and resource inefficiencies

Focus Areas:

  • N+1 query problems
  • Algorithmic complexity (O(n²) → O(n log n))
  • Memory leaks
  • Missing database indexes
  • Inefficient loops and iterations
  • Resource exhaustion risks
  • Caching opportunities
  • Blocking operations in async code

Expertise: Big-O analysis, profiling patterns, database optimization

🎭

Theatre Detector

Claude Opus 4.5 + ultrathink

Mission: Identify tests that pass but verify nothing (must run BEFORE coverage analyzer)

Focus Areas:

  • Hardcoded input/output tests
  • Empty test bodies (pass, ...)
  • Always-pass assertions (assert True)
  • Over-mocked tests (3+ patches)
  • Mock-only assertions
  • Tautological tests
  • Exception swallowing
  • Conditional assertions
  • Trivial assertions

Expertise: False confidence detection, test anti-patterns

Critical: Must run before Test Evaluator to exclude theatre from coverage metrics

🧪

Test Evaluator

Claude Opus 4.5 + ultrathink

Mission: Assess test coverage, quality, and maintainability (excludes theatre tests)

Focus Areas:

  • Test coverage gaps
  • Missing edge case tests
  • Flaky test patterns
  • Test maintainability
  • Assertion quality
  • Test data management
  • Integration vs unit test balance
  • Mock overuse/misuse

Expertise: Testing pyramid, TDD principles, test patterns

Dependency: Requires Theatre Detector output to exclude fake tests from metrics

✨

Code Style Checker

Claude Opus 4.5 + ultrathink

Mission: Ensure readability, consistency, and documentation quality

Focus Areas:

  • Naming conventions
  • Code formatting consistency
  • Documentation completeness
  • Comment quality
  • Function length and complexity
  • Magic numbers and constants
  • Dead code and unused imports
  • Readability improvements

Expertise: Style guides, clean code principles, documentation standards

Fix Agents (2)

These agents run during --fix mode as parallel subagents. Each starts with fresh context (no inheritance from review phase) to prevent context bloat and eliminate compaction.

🔧

Omnibus Fixer

Claude Opus 4.5

Mission: Apply COMPLETE fixes to a single file following a structured fix plan

Focus Areas:

  • Root cause fixes (not symptoms)
  • Architecture alignment
  • Pattern consistency with codebase
  • Edge case handling
  • Type safety preservation
  • Divergence documentation

Key Principles:

  • No shortcuts or quick fixes
  • Must fit existing architecture
  • Updates fix plan with status
  • Documents reasons for divergence

Input: Single file + YAML fix plan

Output: Updated fix plan with actual_fix and status per finding

✓

Omnibus Validator

Claude Opus 4.5

Mission: Verify fixes are complete, correct, and match the fix plan

Focus Areas:

  • Fix application verification
  • Completeness assessment
  • Architecture compliance
  • Divergence evaluation
  • Regression detection
  • New issue identification

Catches:

  • Incomplete fixes (shortcuts)
  • Fixes not matching plan
  • Invalid divergence reasons
  • Regressions introduced
  • Architecture violations

Input: Updated fix plan + git diff

Output: Validation report (pass/fail per finding)

Agent Collaboration Patterns

Independent but Complementary

Agents work in isolation during Phase 2 but their findings often overlap in beneficial ways:

  • Security + Correctness: SQL injection (security) + unvalidated input (correctness) = high confidence finding
  • Performance + Architecture: N+1 queries (performance) + tight coupling (architecture) = systemic issue
  • Theatre + Test: Theatre tests (theatre detector) filtered before coverage analysis (test evaluator) = accurate metrics
  • Test + Correctness: Missing tests (test) + edge case bugs (correctness) = coverage gap
  • Style + Architecture: God object (architecture) + poor naming (style) = maintainability problem

Agreement Signals Quality

When multiple agents independently identify the same issue, it's a strong signal:

Agent Overlap Confidence Boost Interpretation
2 agents agree +0.1 Independent verification, likely real issue
3+ agents agree +0.15 Strong consensus, definitely needs attention
Security + Correctness +0.15 + severity upgrade Exploitable bug, highest priority
No overlap 0 Unique perspective, evaluate on confidence alone

Domain Boundaries

Each agent respects domain boundaries to avoid redundant analysis:

  • Security: Focuses on exploitability, not implementation quality
  • Architecture: Design patterns, not specific bugs
  • Correctness: Logic errors, not performance
  • Performance: Resource efficiency, not correctness
  • Test: Test quality only, not production code style
  • Style: Readability and consistency, not functionality

Why Claude Opus 4.5 + Ultrathink?

Model Selection Rationale

All six agents use Claude Opus 4.5 with ultrathink extended thinking for maximum quality:

  • Deep Reasoning: Security and correctness analysis require multi-step logical reasoning
  • Context Mastery: Understanding large codebases with complex dependencies
  • False Positive Reduction: Nuanced judgment to distinguish real issues from patterns that look suspicious but are intentional
  • Cross-Language Expertise: Strong performance across Python, JavaScript, TypeScript, Go, Rust, etc.

Ultrathink Benefits

Extended thinking mode allows agents to:

  • Consider multiple hypotheses before reporting
  • Trace execution paths through complex control flow
  • Evaluate security implications of seemingly benign code
  • Recognize subtle architectural violations
  • Perform deeper static analysis than standard models

Trade-offs

  • Speed: 2-3x slower than Sonnet, but thoroughness justifies the time
  • Cost: Higher per-review cost, but fewer false positives means less wasted engineering time
  • When to Use: Pre-merge reviews, security audits, major refactors - not for every commit
