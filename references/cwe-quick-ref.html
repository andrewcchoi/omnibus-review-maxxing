About CWE

Common Weakness Enumeration (CWE) is a community-developed list of software and hardware weakness types. It serves as a common language for describing security vulnerabilities and provides a baseline for weakness identification, mitigation, and prevention efforts.

Maintained by: MITRE Corporation
Official Site: https://cwe.mitre.org
Used in: CVE entries, security tools, compliance frameworks

OWASP Top 10 - Mapped CWEs

Most common web application security risks and their associated CWEs

CWE-89
CRITICAL

SQL Injection

OWASP: A03:2021 - Injection
Description: Software constructs SQL queries from user input without proper neutralization, allowing attackers to modify query structure.
Vulnerable Code:
query = f"SELECT * FROM users WHERE id = {user_id}"
cursor.execute(query)
Remediation:
• Use parameterized queries or prepared statements
• Use ORM frameworks with built-in protections
• Validate and sanitize all inputs
• Apply principle of least privilege to database accounts
CWE-78
CRITICAL

OS Command Injection

OWASP: A03:2021 - Injection
Description: Application executes OS commands constructed from user input, allowing attackers to execute arbitrary system commands.
Vulnerable Code:
import os
os.system(f"ping {user_input}")
Remediation:
• Use subprocess with argument lists, never shell=True
• Validate input against strict whitelist
• Use libraries instead of shell commands when possible
• Run with minimal privileges
CWE-79
HIGH

Cross-Site Scripting (XSS)

OWASP: A03:2021 - Injection
Description: Application includes untrusted data in web page without proper validation or escaping, allowing attackers to execute scripts in victim's browser.
Vulnerable Code:
return f"<div>Hello {username}</div>"
Remediation:
• HTML-escape all user input in templates
• Use Content Security Policy (CSP) headers
• Use auto-escaping template engines
• Validate input on server side
CWE-798
CRITICAL

Use of Hard-coded Credentials

OWASP: A07:2021 - Identification and Authentication Failures
Description: Software contains hard-coded credentials (passwords, API keys) that cannot be changed without code modification.
Vulnerable Code:
API_KEY = "sk_live_abc123xyz789"
DB_PASSWORD = "admin123"
Remediation:
• Use environment variables for all secrets
• Use secret management systems (Vault, AWS Secrets Manager)
• Rotate exposed credentials immediately
• Never commit secrets to version control
CWE-862
HIGH

Missing Authorization

OWASP: A01:2021 - Broken Access Control
Description: Software does not perform authorization checks for sensitive operations, allowing unauthorized access.
Vulnerable Code:
@app.delete("/users/{user_id}")
async def delete_user(user_id: int):
    # No check if current user can delete this user
    await user_repo.delete(user_id)
Remediation:
• Implement authorization checks on all sensitive endpoints
• Use role-based access control (RBAC)
• Deny by default, explicitly allow
• Test authorization boundaries
CWE-502
HIGH

Deserialization of Untrusted Data

OWASP: A08:2021 - Software and Data Integrity Failures
Description: Application deserializes untrusted data without verification, potentially allowing code execution or data tampering.
Vulnerable Code:
import pickle
data = pickle.loads(user_input) # DANGEROUS
Remediation:
• Never deserialize untrusted data
• Use safe formats (JSON) instead of pickle/marshal
• Validate deserialized object structure
• Use digital signatures for serialized data
CWE-287
HIGH

Improper Authentication

OWASP: A07:2021 - Identification and Authentication Failures
Description: Authentication mechanism can be bypassed or is insufficiently robust.
Vulnerable Code:
if password == stored_password: # Plain text comparison
    login_user()
Remediation:
• Use bcrypt/argon2 for password hashing
• Implement multi-factor authentication
• Use secure session management
• Implement account lockout after failed attempts
CWE-327
HIGH

Use of Broken/Risky Cryptographic Algorithm

OWASP: A02:2021 - Cryptographic Failures
Description: Software uses weak or broken cryptographic algorithms that can be broken.
Vulnerable Code:
import hashlib
hash = hashlib.md5(password) # MD5 is broken
hash = hashlib.sha1(password) # SHA1 is weak
Remediation:
• Use bcrypt, scrypt, or argon2 for passwords
• Use SHA-256 or SHA-3 for hashing
• Use AES-256 for encryption
• Keep crypto libraries updated
CWE-306
HIGH

Missing Authentication for Critical Function

OWASP: A07:2021 - Identification and Authentication Failures
Description: Critical functionality lacks authentication requirement, allowing anonymous access.
Vulnerable Code:
@app.post("/admin/delete-all-users")
async def delete_all(): # No auth check!
    await user_repo.delete_all()
Remediation:
• Require authentication for all non-public endpoints
• Use authentication middleware/decorators
• Default to authenticated, explicitly mark public routes
• Audit all endpoints for auth requirements
CWE-352
MEDIUM

Cross-Site Request Forgery (CSRF)

OWASP: A01:2021 - Broken Access Control
Description: Application does not verify that requests come from legitimate users, allowing forged requests.
Vulnerable Code:
@app.post("/transfer-money") # No CSRF protection
async def transfer(amount, to_account):
    process_transfer(amount, to_account)
Remediation:
• Use CSRF tokens for state-changing operations
• Use SameSite cookie attribute
• Verify Origin/Referer headers
• Use framework CSRF protection (Django, Flask-WTF)
CWE-916
MEDIUM

Use of Password Hash with Insufficient Computational Effort

OWASP: A02:2021 - Cryptographic Failures
Description: Password hash can be cracked quickly due to low computational cost.
Vulnerable Code:
hash = hashlib.sha256(password).hexdigest() # Too fast!
bcrypt.hashpw(pw, bcrypt.gensalt(rounds=4)) # Too few rounds
Remediation:
• Use bcrypt with 12+ rounds
• Use argon2id (current best practice)
• Use scrypt with high parameters
• Regularly increase work factor as hardware improves
CWE-200
MEDIUM

Exposure of Sensitive Information

OWASP: A02:2021 - Cryptographic Failures
Description: Software exposes sensitive information to unauthorized actors through various means.
Vulnerable Code:
return {"user": user, "password_hash": user.password} # Exposed
logging.info(f"Login failed for {email} with {password}") # Logged
Remediation:
• Never return sensitive fields in API responses
• Sanitize logs to remove sensitive data
• Use proper error messages (don't leak info)
• Implement data classification and handling policies

Severity Mapping Guide

General guidelines for mapping CWEs to omnibus-review severity levels:

CWE Category Typical Severity Conditions for Upgrade
Remote Code Execution CRITICAL Always critical
SQL/Command Injection CRITICAL Production code; HIGH if dev-only
Hard-coded Credentials CRITICAL Production keys; HIGH if test keys
Authentication Bypass CRITICAL Admin/financial; HIGH for user features
XSS HIGH Stored XSS = CRITICAL; Reflected = HIGH
Missing Authorization HIGH Financial/admin = CRITICAL; user features = HIGH
Insecure Deserialization HIGH Untrusted input = CRITICAL; internal = HIGH
Weak Crypto HIGH Passwords/sensitive = HIGH; non-security = MEDIUM
CSRF MEDIUM Financial operations = HIGH; other = MEDIUM
Information Disclosure MEDIUM PII/passwords = HIGH; technical info = MEDIUM
Missing Input Validation MEDIUM Security-critical path = HIGH; other = MEDIUM
